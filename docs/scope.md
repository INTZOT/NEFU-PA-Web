# P1 范围声明（Scope Statement）

> **本文件的用途**：用一页纸说清"这个项目做什么、不做什么"，供你逐条核对。
> **状态**：待你确认（P1 阶段唯一产出）
> **依据**：`docs/decisions.md` 的 16 条决策 + `docs/requirements.md` 的 44 条需求

## 一、一句话定义

> 为东北林业大学匹克球社团建设一个**以移动端为主、从 QQ 群进入、面向成员日常使用**的官方网站；它同时承担对外展示与内部服务两种角色，日常运行尽可能不依赖人工维护。

---

## 二、范围之内（In Scope）

### 2.1 五个核心模块

| 编号 | 模块 | 一句话说明 | 谁能用 |
| --- | --- | --- | --- |
| M1 | **社团介绍** | 对外名片：社团概况、组织、联系方式、加入方式 | 游客 |
| M2 | **社团公告** | 官方通知发布与浏览 | 游客（可见性见待定项） |
| M3 | **官方活动** | **仅报名侧**：发布赛事 → 报名 → 名额/候补 → 搭档登记 → **签到**；可取消（赛前 24h）；**赛事组织在线下**；赛后管理员录入对局数据结算积分 | 浏览公开 / 报名限成员 |
| M4 | **约球大厅** | 成员发起房间 → 他人申请 → 发起人审批 | 仅成员 |
| M5 | **积分与排行** | 自评分（自报、可改、约球可见）+ 比赛积分（仅官方比赛、起 500、**按赛季归档**）→ 排行榜只排比赛积分、**可切换历史赛季** | 仅成员 |

### 2.2 一个地基子系统

| 编号 | 子系统 | 包含 |
| --- | --- | --- |
| S1 | **账号体系** | 邀请码注册、双标识登录（QQ 号 / 学号 + 密码）、自助换绑、机器人重置密码、个人主页 |
| S2 | **QQ 机器人（配套）** | 签发邀请码、提供注册链接、重置密码。**第三方框架 + 你自己写逻辑**；它是**无状态薄客户端**，全部业务数据存于网站侧（[D-19](decisions.md)）—— 属于配套交付物，不在网站本体范围内 |
| S3 | **管理员能力** | 发布公告与活动 + 账号人工兜底 |
| S4 | **机器人对接** | **机器人直连数据库**读写：生成邀请码、查询注册状态、写入密码。需**专用受限数据库账号**；表结构是机器人与网站的**共享契约**（[D-19](decisions.md)） |
| S5 | **赛季** | 一级实体：起止时间（管理员配置）、名称（如 `2025/2026`）；对局归属赛季；结束当天自动归档；支持历史查看（[D-25](decisions.md)） |
| S6 | **录入成绩入口** | 管理员**逐场录入对局数据**，系统按**标准 ELO（K=40）**结算比赛积分（[R-92](requirements.md)、[R-96](requirements.md)） |

## 四、关键参数速查

| 项目 | 取值 |
| --- | --- |
| 权限层次 | 游客 / 成员 / 管理员 |
| 学号格式 | 10 位数字，如 `2025213063`（仅格式校验） |
| 积分构成 | **两个独立量**：**个人自评分**（自报，不随比赛变化，可随时改）+ **比赛积分**（**仅官方比赛**产生） |
| 自评分范围 | **0–1000**，注册后**引导**滑动选择；**对约球者可见** |
| 比赛积分初始值 | **一律 500** |
| 结算方式 | **标准 ELO**，**K = 40**，零和；双打取搭档**平均分**、两人**增减相同**（同分时各 ±20） |
| 成绩录入 | 管理员赛后**逐场录入对局数据** |
| 报名规则 | 名额**双打按队、单打按人**；**可取消**（赛前 24 小时）；**需要签到** |
| 机器人访问方式 | **直连数据库**（需专用受限账号；表结构为共享契约） |
| 积分档位 | 五档：**小白 / 新手 / 熟手 / 高手 / 大师**；**仅作为选择自评分时的参考，不跟随展示** |
| 排行榜 | **只排比赛积分**（方案 B），无自评分榜；**场次/胜率仅统计官方比赛** |
| 赛季 | **一赛季 = 一学年**（命名如 `2025/2026`）；乙式归档、历史保留可查看；起止由管理员配置、**学年结束当天自动归档**；每赛季积分独立、新成员每赛季起 **500** |
| 休赛期 | **寒暑假不开展官方活动**；**约球不受限制** |
| 日期容错 | 未配置新学期日期则**沿用上学期**；修改起止日期**不追溯**已产生的对局 |
| 内容同步 | 网站与 QQ 群**手动双发**，无自动同步 |
| 权限模型 | **超级管理员**（**预先指定**、可共用）→ 可设置管理员 → 成员 → 游客 |

| 对局确认时限 | 24 小时 |
| 约球房间过期 | 24 小时 |
| 对局结算 | 双打取搭档平均分 → 按单打方式结算 |
| 排行榜 | 积分榜 + 场次/胜率榜，单双不分 |
| 约球房间字段 | 时间段、人数上限、备注 |

## 七、本项目的成立前提（非网站本身的工作量）

| 前提 | 说明 |
| --- | --- |
| P1 | **QQ 机器人必须存在且可用** —— 它是准入的唯一入口。**已改为接入现有开源项目 + 你提供账号的路线**（第 8 轮），但存在一个必答的能力前提：见 [Q33](open-questions.md)。 |
| P2 | 服务器 / 域名 / 部署环境（Q5） |
| P3 | 社团侧的运营：场地协调、活动组织等（不属本项目） |
| P4 | **机器人侧的自定义逻辑由你自己实现**：转发注册/重置请求、读取 QQ 号、向网站查询 —— 这是独立于网站的一份开发量 |
| P4c | ✅ 已定：机器人数据**存网站侧**，机器人是**无状态薄客户端**，因此换号**不需数据迁移**（[D-19](decisions.md)） |
| P4b | **机器人走第三方框架路线**（[D-17](decisions.md)），身份锚点为真实 QQ 号；账号处于灰色地带 |
| P5 | ⚠️ **QQ 账号被封风险（已明确接受）**：第三方框架的账号可能被封。**你选择不设备用账号、不保留兜底通道**，靠"换新账号"快速恢复（[D-17](decisions.md)）。被封期间**新人无法注册**，且无第二条路径 |

> ⚠️ **P1 是硬前提**：如果没有可用的 QQ 机器人，[D-12](decisions.md) 的整套注册流程无法成立，S1 账号体系需重新设计。这是**唯一可能推翻既有架构的外部依赖**。
